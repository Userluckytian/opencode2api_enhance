# 按天问题/需求日志(强制维护)

> **规则来源:** `AGENTS.md` 强制遵循第 6 条 · `CLAUDE.md` 日志条款
> **适用:** 本项目所有 AI(OpenCode / Grok / Codex / Claude / 海鸥)与协作者

## 目的

本项目每个工作日维护一份日志,记录当天提出的**每个问题 / 需求**、问题分析、修改结果,并在修复后及时更新状态。避免「几天后记不清之前做过什么」。

## 目录与命名

```
docs/issue-log/
├── README.md          # 本文件(约定)
├── OPEN.md            # ★ 开放事项索引——只放未关闭项(AI 每天开工只读它)
├── 2026-08-17.md      # 按天日志,文件名 YYYY-MM-DD.md
├── 2026-08-18.md
└── ...
```

- 每天一个文件,文件名 `YYYY-MM-DD.md`(UTC+8 工作日)。
- 当天没有问题时也建文件,写「今日无待办问题」,保证时间线连续。
- 跨天未修复的问题:**照抄进次日文件**,保持可见,直到关闭。
- **`OPEN.md` 是「开放事项索引」**:只汇总**尚未关闭**的项,历史明细留在各日期文件里,不在 OPEN.md 重复抄写。

## OPEN.md(开放事项索引)——AI 每天开工的第一读

> **为什么有它:** 未完成事项可能散落在 30 个历史日志里,AI 每次全量翻找既费 token 又慢。OPEN.md 始终是一个**小文件**,把「当前有哪些事没做完」集中在一处,AI 读它一个文件就能掌握全局,需要细节时再按链接读对应日期日志。

**OPEN.md 模板:**

```markdown
# 开放事项索引(未关闭项)

> 规则:每天开工先读本文件掌握未完成事项;每天收工把当天仍未关闭的项同步进来,已关闭的移出。
> 状态:待处理 / 修复中 / 已修复待验证。已关闭项不在此文件,历史留在各日期日志。

| 日期 | 事项 | 状态 | 详情 |
|------|------|------|------|
| 2026-08-17 | <一句话标题> | 待处理 | [2026-08-17.md](2026-08-17.md) |

（今日无未关闭项则写「暂无」）
```

**OPEN.md 维护规则（三个动作，事件驱动）：**

> OPEN.md 是「活清单」，不是每天重写——只有状态变化时才动它。维护它的是 AI（处理问题时**顺手同步**，一次操作两处更新：当天日志 + OPEN.md），用户无需手动维护。

1. **新增**（新问题出现时）：在当天日志记录问题的同时，往 OPEN.md **加一行** `| 日期 | 事项 | 状态 | 详情 |`。
2. **更新**（状态变化时）：问题状态变了（待处理 → 修复中 → 已修复待验证），同步改 OPEN.md 对应行的状态列。
3. **移除**（问题关闭时）：验证通过、在日志里标「已关闭」时，**删除** OPEN.md 对应行——关闭项不留索引（已关闭的历史留在各日期日志里）。

**同步时机：** 每个问题状态变化时（实时顺手做）+ 每天结束时（兜底核对，确保 OPEN.md 与当天日志一致）。全部关闭时 OPEN.md 变空表（写「暂无」）。
**它不抄正文**，只做索引（日期 + 事项 + 状态 + 链接），所以永远很小。

## 单日文件模板

```markdown
# 2026-08-17 问题/需求日志 — opencode2api_enhance

> 状态汇总:待处理 N · 修复中 M · 已修复待验证 K · 已关闭 P

## 问题 / 需求列表

### 1. <一句话标题>

- **类型:** 问题 / 需求 / 优化
- **提出人:** <谁提的>
- **状态:** 待处理 → 修复中 → 已修复待验证 → 已关闭
- **提出时间:** 2026-08-17 10:30

**问题/需求描述:**
<原始描述,尽量保留用户原话>

**分析:**
<根因分析、影响范围、相关文件/模块>

**修改结果:**
<实际改了什么:文件、命令、验证结果(真实输出)>

**遗留/风险:**
<未解决的部分、后续注意点> (可空)
```

## 状态定义

| 状态 | 含义 | 更新时机 |
|------|------|---------|
| 待处理 | 已提出,未开始 | 记录时 |
| 修复中 | 正在改 | 开始动手时 |
| 已修复待验证 | 改完,待测试/验收 | 代码改完时 |
| 已关闭 | 验证通过,结案 | 测试通过时(附证据) |

## 维护规则(所有 AI 必须遵守)

1. 处理**任何**问题/需求时,同步更新当日 `YYYY-MM-DD.md`(新建或追加)。
2. 状态变化实时更新;修复后**必须**把「已修复待验证」改为「已关闭」并附验证证据。
3. 未关闭项次日**自动带过**(复制到新文件,不得静默消失)。
4. 每个条目至少包含:描述 / 分析 / 修改结果 / 状态 四要素。

## 入库策略(git)

**只入库约定文档 `README.md`,每日日志 `YYYY-MM-DD.md` 一律不入库**(本地研发笔记)。

安装本框架时已自动在项目 `.gitignore` 写入:

```gitignore
# 按天问题日志（只入库约定文档 README.md，每日日志本地保留不入库）
docs/issue-log/*
!docs/issue-log/README.md
```

- 每日日志是**本地研发过程笔记**,不随仓库分发(和 `docs/AI-TESTING-GUIDE.md` 等本地文档同策略)。
- 提交前核对 `git status`,确认 `docs/issue-log/YYYY-MM-DD.md` 未出现在暂存区。
- 若你的团队希望日志也入库,删除 `.gitignore` 中上述两行即可。
