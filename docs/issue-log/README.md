# 按天问题/需求日志(强制维护)

> **规则来源:** `AGENTS.md` 强制遵循第 6 条 · `CLAUDE.md` 日志条款
> **适用:** 本项目所有 AI(OpenCode / Grok / Codex / Claude / 海鸥)与协作者

## 目的

本项目每个工作日维护一份日志,记录当天提出的**每个问题 / 需求**、问题分析、修改结果,并在修复后及时更新状态。避免「几天后记不清之前做过什么」。

## 目录与命名

```
docs/issue-log/
├── README.md          # 本文件(约定)
├── 2026-08-17.md      # 按天日志,文件名 YYYY-MM-DD.md
├── 2026-08-18.md
└── ...
```

- 每天一个文件,文件名 `YYYY-MM-DD.md`(UTC+8 工作日)。
- 当天没有问题时也建文件,写「今日无待办问题」,保证时间线连续。
- 跨天未修复的问题:**照抄进次日文件**,保持可见,直到关闭。

## 单日文件模板

```markdown
# 2026-08-17 问题/需求日志 — opencode2api_enhance

> 状态汇总:待处理 N · 修复中 M · 已修复待验证 K · 已关闭 P

## 问题 / 需求列表

### 1. <一句话标题>

- **类型:** 问题 / 需求 / 优化
- **提出人:** <谁提的>
- **状态:** 待处理 → 修复中 → 已修复待验证 → 已关闭
- **提出时间:** 2026-08-17 10:30

**问题/需求描述:**
<原始描述,尽量保留用户原话>

**分析:**
<根因分析、影响范围、相关文件/模块>

**修改结果:**
<实际改了什么:文件、命令、验证结果(真实输出)>

**遗留/风险:**
<未解决的部分、后续注意点> (可空)
```

## 状态定义

| 状态 | 含义 | 更新时机 |
|------|------|---------|
| 待处理 | 已提出,未开始 | 记录时 |
| 修复中 | 正在改 | 开始动手时 |
| 已修复待验证 | 改完,待测试/验收 | 代码改完时 |
| 已关闭 | 验证通过,结案 | 测试通过时(附证据) |

## 维护规则(所有 AI 必须遵守)

1. 处理**任何**问题/需求时,同步更新当日 `YYYY-MM-DD.md`(新建或追加)。
2. 状态变化实时更新;修复后**必须**把「已修复待验证」改为「已关闭」并附验证证据。
3. 未关闭项次日**自动带过**(复制到新文件,不得静默消失)。
4. 每个条目至少包含:描述 / 分析 / 修改结果 / 状态 四要素。
