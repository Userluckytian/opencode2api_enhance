# 插件能力清单（Plugin Capability Catalog）

> 面向 **opencode2api 插件式供应商** 作者的完整能力目录。
> 与 `docs/PLUGIN-PROVIDERS.md` 的关系：那里是**契约（P0，违反即拒载）**，这里是**能力菜单（P0~P3，按上游与场景自选）**。
> 用法：先满足 P0；再从 P1/P2/P3 里选。不要因为"别人有"就硬加——上游没有的能力做出来也是假数据。
> 最后更新：2026-11-04

---

## 0. 先选插件类型

| 类型 | 特征 | 典型插件 | 必选能力 |
|---|---|---|---|
| **号池型** | 多账号、轮询/切号、额度管理 | RunBios、QwenWork、Skywork、BuddyHub、MiniMax | A/B/C/D/E/I/J 的 P0+P1 |
| **单账号型** | 一个 session/cookie，无池 | LOOMy、VibeX | A1/A3、B1、C1/C2、H1、I/J |
| **注册型** | 核心是自动注册 + 入池 | Flonno、Grok、QwenWork、MiniMax | F 组为主 + A/B/D/I/J |
| **聚合/桥接型** | 只做协议适配，不持有账号 | VibeX | C1/C4、H1、I/J |

> 一个插件可以同时是"号池型 + 注册型"（QwenWork/Skywork/MiniMax）。

---

## 1. 能力等级定义

| 等级 | 含义 | 不做的后果 |
|---|---|---|
| **P0** | 契约强制，宿主校验 | 拒载/启动失败/安全边界失效 |
| **P1** | 强烈建议，直接影响可用性 | 能用但难用：空目录、看不到额度、切号不生效 |
| **P2** | 按上游政策/场景选择 | 上游没有就别做；做了要有真实数据来源 |
| **P3** | 进阶/锦上添花 | 不影响主流程 |

## 3. 事件日志（C8）规范

> 目标：回答"什么时候注册成功/失败、签到、切号、额度刷新、账号删除"。

### 3.1 字段

| 字段 | 必填 | 示例 |
|---|---|---|
| `ts` | 是 | `2026-11-04T15:36:49+08:00` |
| `level` | 是 | `info/warn/error` |
| `plugin` | 是 | `grok` |
| `type` | 是 | `register.success` |
| `account` | 否 | `xxx@gmail.com` / `Cody` |
| `message` | 是 | `注册成功，已入池` |
| `meta` | 否 | `{"model":"...","credits":12.5,"attempt":2}` |
| `request_id` | 否 | `req_xxx` |

### 3.2 类型

- 账号：`account.add/delete/disable/import`
- 注册：`register.start/success/fail/import`
- 签到：`checkin.start/success/fail`、`task.done`
- 调度：`switch.quota`(402)、`switch.rate`(429)、`switch.auth`(401)、`switch.error`(5xx)
- 额度：`quota.refresh/low/reset`
- 系统：`plugin.start/stop`、`config.change`、`net.switch`

### 3.3 存储/接口/UI

- `data/events.jsonl` 追加写；10MB×5 或 30 天；启动加载尾部 N 条。
- `GET /api/events?level=&type=&account=&since=&limit=`；`GET /api/events/export`。
- 面板"日志"页：chips（全部/注册/签到/切号/账号/异常）+ 搜索 + 时间范围 + 5s 刷新 + 导出。
- 写失败降级到 stderr，不影响主流程。

## 4. 模型目录元数据（C4）规范

宿主 `vendors/remote` 只解析两个键：**`context_window`** 与 **`max_output_tokens`**（见 `remote.go:107-108`）。

| 键 | 类型 | 说明 |
|---|---|---|
| `context_window` | int | 上下文窗口（token） |
| `max_output_tokens` | int | 最大输出（token）；未知则省略，不要填 0 |
| `context_length` | int | **兼容字段**，宿主不读；可双写，但不能只写它 |
| `context_window_options` | int[] | **可选**：上游支持多档上下文时（如 MiniMax `[512000,1000000]`），不要只报默认值；用独立模型 id/别名或面板选择透出 |
| `context_window_option_hints` | object | 可选：档位提示（如 `{"1000000":"higher_usage"}`），用于 UI 标注"更贵" |
| `capabilities` | object | 可选，扩展能力 |

**数据来源优先级**：
1. 上游模型目录的权威字段（如 MiniMax `limit.context/output` + `context_window_options`、Grok `upstream_profile.ContextWindow/MaxCompletionTokens`）；
2. 上游 `/v1/models` 的真实字段（`context_length` 可映射到 `context_window`）；
3. 本地静态表/缓存（要标注"估算"）；
4. 兜底默认值（必须可配置、可关闭，不能把 1M 的模型标成 131K）。

**多档上下文（重要）**：
- `limit.context` 是**默认值**，不一定是上限；有 `context_window_options` 时必须读；
- 推荐用**独立模型 id/别名**（如 `MiniMax-M3.1-Flash-1M`）表示 1M 档，避免"客户端以为默认 1M"；
- 请求里要真正传 `context_limit`（不同上游字段名可能不同），否则只是显示 1M、实际仍 512K；
- 1M 档通常 `higher_usage`，计费/提示要跟上。

**反面案例**：
- 只写 `context_length`（宿主忽略）→ 面板"没有上下文"；
- 只读 `limit.context`、忽略 `context_window_options` → 1M 档看不见；
- 给所有模型无条件注入 131072 → 1M 模型被截断；
- 把 `max_output_tokens` 填 0/空字符串 → 宿主省略或显示 0。

## 5. 账号删除生命周期（A10）规范

> 来自 Grok 的真实教训：DB 删了、文件没删，注册后全量导入把已删账号带回来。

删除一个账号必须同时处理：

1. **DB/池记录**：删除账号行；
2. **本机凭证文件**：`xai-*.json`、`*.txt` 中的匹配行/文件；
3. **关联账号**：build/web/console 关联（可选连带）；
4. **冷却/粘性会话**：清掉该账号的 sticky/cooldown；
5. **统计/日志**：保留历史，但标记"已删除"；
6. **导入策略**：注册后只导入**新增/变更**文件，不要全量 re-import；
7. **孤儿清理**：提供"文件有、DB 无"的一键清理；
8. **UI 确认**：显示"账号 N + 文件 M + 关联 K"。

验收：删除 → 再注册 → 重启 → 该账号**不再出现**。

## 6. 数据与 profile 规范（I1/I7）

- 所有运行数据写 `<插件>/data/`；账号/额度/日志/事件/任务/缓存都在这里。
- 浏览器 profile：
  - 自动注册：**临时 profile**（每次新建、结束清理）优先；确需 warm profile 时放 `data/chrome-autoreg`，加 TTL/清理；
  - 人工登录：`data/browser-profile`，可保留，但要清缓存/组件，目标 <200MB；
  - **禁止**两个插件共享同一个 `user-data-dir`。
- 日志：`data/*.log` 必须轮转；`data/events.jsonl` 单独轮转。
- 升级：覆盖 exe 时排除 `data/`；先备份再替换。

## 8. 反模式（明确不要做）

1. **假数据**：上游没给上下文/输出，却硬填 1M/128K；或把 `context_length` 当 `context_window` 只写一个。
2. **删除只删 DB**：文件还在，注册后全量导入 → 账号复活。
3. **全量 re-import**：每次注册都扫全目录导入，已删账号必回。
4. **共享 profile/refresh token**：两个插件/两个部署共用同一 `user-data-dir` 或同一份一次性 token。
5. **把数据写进源码仓库/用户目录**：`auth_dir` 写绝对路径、`%APPDATA%` 默认、`~/.qw2api` 游离。
6. **静默失败**：配置键写了不生效、面板返回 200 但 `{error}`、删除 0 条却报成功。
7. **无限重试/无上限日志**：429 无限重试、日志 100MB 不轮转。
8. **面板当摆设**：只有原始日志抽屉，没有结构化事件/额度/调用记录。
9. **跨仓库共享 Go 包**：把 UI/协议耦合进一个模块，发布互相拖累。
10. **动效过度**：表格页大面积 canvas、无限循环背景、无 `prefers-reduced-motion` 降级。
