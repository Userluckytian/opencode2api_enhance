# 网页自助领 Key 服务（Web Self-Service）设计文档

> 日期：2026-08-05
> 分支：`feature/web-self-service`
> 状态：设计已确认
> **端口更新（2026-08-06）：三环境端口隔离后，web 服务端口已由 18081 改为 23081**（下文示例中的 18081 均为历史值）

## 目标

在现有 opencode2api 管理器（桌面版）之外，提供一个**纯网页版的广告分发服务**：用户打开浏览器就能自助领取一个 API Key，把它配到自己客户端（OpenCode / Cherry Studio 等）使用；管理员通过网页后台统一设置参数、管理 Key、查看用量。部署为**单个 Go 程序全包、后台常驻**。

本设计不涉及远程推送，仅本地提交。

## 背景与现状

- 现有桌面版是一个 Tauri 2 + Rust 的管理器，管理多个 opencode2api 代理实例，每个实例通过 sing-box 走代理节点连接 OpenCode。桌面版明确不监听 HTTP 端口。
- 网页版是**独立程序**，只负责：① 提供领 Key 页面与管理后台网页；② 作为 API 网关校验 Key 并**转发**给用户配置的上游实例。**不做**协议转换、**不**直接连接 OpenCode。

## 需求

### 用户侧（领 Key 页面）
1. 打开网页看到可选模型列表（后台白名单，自动从上游 `/v1/models` 拉取 + 后台勾选）。
2. 选择模型 → 点击「获取 Key」→ 页面显示「访问地址 + Key」并支持一键复制。
3. 用户把「地址 + Key」配置到自己的客户端（OpenCode / Cherry Studio / Cursor 等），客户端通过 `http://<host>:<port>/v1` 调用。
4. Key 绑定所选模型：客户端请求的模型必须等于 Key 绑定的模型，否则拒绝。
5. 访问不设限制：任何人均可领取，可领多个。

### Key 参数（全局统一，后台可调）
| 参数 | 默认值 |
|------|--------|
| 有效期 | 7 天 |
| 总 token 额度 | 1,000,000 |
| 限速 | 每分钟 30 次 |

### 管理后台（管理员入口 + 密码弹窗登录）
- 设置全局参数：有效期、token 额度、限速、上游实例地址。
- 模型白名单：自动拉取上游全部模型，勾选允许分发的模型。
- 查看 Key 列表（领取时间、过期时间、剩余额度、状态、绑定模型）。
- 手动禁用 / 启用 / 删除 Key。
- 概览统计（Key 总数、在用数、请求数、token 消耗）。
- 查看单个 Key 的调用记录（可按 Key / 时间筛选）。
- 修改管理员密码。

## 架构

```
┌─────────────────────────────────────────────────┐
│  浏览器（任何人）                                 │
│  ① 领 Key 页面  ② 管理后台（密码进入）            │
└────────────────────┬────────────────────────────┘
                     │ HTTP
┌────────────────────▼────────────────────────────┐
│  网页版服务（单个 Go exe，监听 18081 端口）        │
│  · 网页托管：内嵌的 HTML/CSS/JS 页面              │
│  · 领 Key 接口：/api/models、/api/keys            │
│  · 管理接口：/api/admin/*（密码校验）             │
│  · API 网关：/v1/*（校验 Key → 限速 → 转发上游）  │
│  · 数据存储：本地文件（配置 + Key + 调用日志）     │
└────────────────────┬────────────────────────────┘
                     │ HTTP 转发（校验通过后）
┌────────────────────▼────────────────────────────┐
│  现有实例（上游地址，如 http://127.0.0.1:18080/v1）│
│  opencode2api + sing-box → 代理节点 → OpenCode    │
└──────────────────────────────────────────────────┘
```

关键点：
- 模型列表通过用户配置的上游实例 `/v1/models` 拉取（上游实例连着 OpenCode），后台据其勾选白名单。
- 单个 Go 程序内嵌网页静态资源，监听 18081，数据存 exe 旁 `web-data/` 目录。
- 转发模式：`/v1/*` 校验通过后原样转发上游对应路径，流式（SSE）透传，无协议转换。

## 页面设计

中文界面，沿用桌面版浅色官网风（底 `#f4f4f5`、白卡片、accent `#0f766e`）。

### 页面① 领 Key 页
- 右上角「管理员入口」小按钮。
- 主体卡片：标题「领取 API Key」、模型下拉框（只显示白名单模型）、「获取 Key」按钮。
- 点击后出现结果卡片：访问地址 + Key + 「一键复制」按钮；下方使用说明小字（如何填入客户端）。

### 页面② 管理后台（密码进入，左侧导航）
- 概览：Key 总数/在用数、请求数、token 消耗总览。
- 模型管理：拉取到的模型列表，勾选允许分发。
- 参数设置：有效期/额度/限速、上游地址、改管理员密码。
- Key 管理：Key 表格（领取时间/过期/剩余额度/状态），禁用/启用/删除。
- 调用日志：记录表格，可按 Key/时间筛选。

## 接口清单

### 用户领 Key 接口（无需登录）
| 接口 | 作用 |
|------|------|
| `GET /` | 返回领 Key 页面 |
| `GET /api/models` | 返回白名单模型列表 |
| `POST /api/keys` | 领取 Key（提交选中模型）→ 返回 `{base_url, key}` |

### 管理接口（需登录令牌）
| 接口 | 作用 |
|------|------|
| `POST /api/admin/login` | 验证管理员密码，发登录令牌 |
| `GET /api/admin/overview` | 概览统计 |
| `GET /api/admin/models` | 拉取上游全部模型 + 当前白名单状态 |
| `POST /api/admin/models` | 保存模型白名单 |
| `GET /api/admin/settings` | 读取参数 |
| `PUT /api/admin/settings` | 保存参数 |
| `PUT /api/admin/password` | 修改管理员密码 |
| `GET /api/admin/keys` | Key 列表 |
| `POST /api/admin/keys/{id}/disable` | 禁用 Key |
| `POST /api/admin/keys/{id}/enable` | 启用 Key |
| `DELETE /api/admin/keys/{id}` | 删除 Key |
| `GET /api/admin/logs` | 调用日志（按 Key/时间筛选） |

### OpenAI 兼容网关（需 Bearer Key）
| 接口 | 作用 |
|------|------|
| `POST /v1/chat/completions` | 聊天补全 |
| `POST /v1/responses` | Responses 协议 |
| `POST /v1/messages` | Anthropic 协议 |
| `GET /v1/models` | 查询可用模型 |

网关通用转发 `/v1/*`：校验通过后按同一路径转发上游，SSE 透传。

## Key 校验流程

```
收到 /v1 请求
→ ① Key 存在？ ② 未禁用？ ③ 未过期（now < expires_at）？
→ ④ 请求 model = Key 绑定 model？ ⑤ 剩余额度 > 0（token_used < quota）？
→ ⑥ 限速未超（每分钟 N 次，按 Key 维度）？
→ 全部通过 → 转发上游
→ 从响应解析 usage → 累加 token_used + 记一条日志
```

## 数据存储

```
web-data/
├── config.json
├── keys.json
└── logs/
    └── log-YYYY-MM-DD.jsonl
```

### config.json
```json
{
  "admin_password_hash": "…",
  "upstream_base_url": "http://127.0.0.1:18080/v1",
  "ttl_days": 7,
  "token_quota": 1000000,
  "rate_limit_per_min": 30,
  "allowed_models": ["glm-4", "kimi-k2"],
  "port": 18081
}
```

### keys.json（每个 Key 一条）
```json
{
  "id": "唯一ID",
  "key": "sk-xxxxxxx",
  "model": "glm-4",
  "created_at": "…",
  "expires_at": "…",
  "token_used": 12345,
  "quota": 1000000,
  "disabled": false
}
```

### logs/ 调用日志（按天分文件，每行一条）
```json
{"time":"…","key_id":"…","model":"glm-4","prompt_tokens":100,"completion_tokens":200,"total":300,"status":200,"ms":1500}
```

## 安全

- 管理员密码只存哈希（如 bcrypt），不存明文。
- Key 用随机字符串生成（`sk-` 开头）。
- 管理接口通过登录令牌（Cookie/Session）鉴权。
- 领 Key 时校验所选模型必须存在于白名单。

## 测试与验收

### 单元测试（Go）
- Key 校验：存在/禁用/过期/额度用尽/模型不匹配各自正确拒绝。
- 限速：超次数被限流。
- 额度扣减：请求后正确累加 token_used。
- 领取校验：模型不在白名单被拒。

### 接口测试（Go httptest）
- 领 Key、登录、设参数、禁用 Key、模型白名单等端点。

### 端到端验收
| 步骤 | 预期 |
|------|------|
| 启动程序，浏览器打开 | 显示领 Key 页面 |
| 选模型 → 点获取 Key | 拿到地址+Key，一键复制 |
| 地址+Key 填进客户端 | 能正常对话 |
| 用别的模型调用 | 被拒绝 |
| 管理员入口 → 输密码 | 进入后台 |
| 后台改参数/勾选模型/禁用 Key | 立即生效 |
| 后台看统计、日志 | 数据正确 |

验收通过标准：端到端流程全部走通。

## 非目标（明确不做）

- 不做前端协议转换（纯转发）。
- 不内嵌代理节点 / 不直接连接 OpenCode。
- ~~不做多上游轮询/容灾（只填一个固定上游地址）~~
  → **2026-10-28 变更**：已支持配置多个上游，按 `model` 第一段的**上游 ID 前缀**路由
  （`backup/gpt-4o` → ID 为 `backup` 的上游，前缀剥离后转发）。仍不做：模型归属自动探测、
  同模型多上游的加权轮询与故障转移、URL 路径前缀路由。详见
  `docs/DEPLOY-WEB.md`「一点六、多上游与 model 前缀路由」与
  `docs/ai-framework/plans/2026-10-28-web-multi-upstream.md`。
- 不做领取访问控制（口令 / IP 限制）。
- 不做 Key 计费 / 充值 / 多套餐。
- 不推送到远程 git，仅本地提交。
